# 蚀骨赠礼 · 初版

在此目录运行 `npm start`，浏览器访问 http://127.0.0.1:5173 。也可以直接打开 index.html，但 ES 模块通常需要通过 HTTP 加载。

- 纯 HTML / CSS / ES modules，无运行时依赖，固定 16:9 舞台等比缩放。
- 三档 8×8 扫雷（8 / 11 / 15 雷）；首击及周围安全，空白连开；不提供手动标记，绿色提示仍可拆开并触发失败。
- 茶壶只检查公开数字：若周围未拆封格数等于数字，则这些格全部有毒。一次显示所有符合规则的格，不做子集或总雷数推理，不读取隐藏雷位。
- 入场提示期间礼物依次放大出现，结束后开始计时。触雷后随机依次揭示蜘蛛，每只蜘蛛先拆封再抖腿，全部动画完成后展示结算。所有连锁拆封格也播放动画，拆封序列使用 mix-blend-mode: exclusion；减少动态效果系统设置会关闭装饰动画。
- 最近 50 条记录、各难度最佳成功成绩存入 localStorage；嵌入时需使用稳定同源才能保留记录。
- 字体优先 assets/font/华康POP1体W5-简体.ttf，备用汉仪第五人格体。
- 动画资源进入游戏后预加载，计时器仅游戏中运行；原始截图和视频不参与游戏加载。当前保留原始 PNG，后续集成可进一步生成压缩资源及动画图集。

`npm test` 运行核心逻辑测试。逻辑位于 engine.js，界面和本地存储位于 app.js，便于后续嵌入。

未提供资源的活动商店、奖励道具不制作。结算使用已提供整屏资源并以 CSS 裁切隐藏左上水印；后续建议提供独立透明卷轴与人物，避免整屏资源中的固定棋盘影响画面边缘。


## 推理优先布雷试版

- 雷数保持 8 / 11 / 15。友善、中立、敌对分别有 0% / 20% / 40% 的概率选择“一次最终二选一”棋盘，其余选择全程可推理棋盘。随机比例不保证每连续十局的固定配额。
- 二选一类型也必须先靠推理排查完其余无毒格，最终只剩一个安全格和一个雷；交换这两个位置不会改变任何已知数字。这是可证明的最终 50/50，不接受中途连续多次猜的候选。
- 生成专用求解器使用数字约束、已证实雷位、总雷数、子集差规则；它与茶壶独立，茶壶继续只使用原有的简单提示规则。候选棋盘能被该求解器完成才通过，并非把“求解器暂时卡住”当成真正无解。
- 首次点击决定布局，此后雷位固定。工作线程在入场时预热，生成耗时不计入通关成绩。
- 工作线程每次随机搜索最多 600 个候选、时间预算 60ms（在单个候选检查结束时检查预算）。达不到要求则使用已验证的种子重新生成同类型棋盘；主线程 1200ms 没收到结果或 Worker 不可用时，也只重建并验证一张预存棋盘，不退回未验证的随机布局。
- 通关后只播放全场 poisoned 确认动画，再显示结算；不触发壶盖动作或茶壶音效。这里根据“所有无毒格已打开”的通关条件确认剩余封闭格，不读取雷位给出游戏中提示。有毒礼物计数显示尚未确认的位置数量，重复提示不重复扣减。
- 每局的生成模式、尝试数、后台计算耗时和往返耗时输出至控制台，并随记录保存在本地，方便试玩评估；不在游戏画面中增加技术提示。

运行 `node tools/benchmark-generation.mjs` 重测生成性能。当前主机 Node v22.18.0 / Windows x64 中，每档 400 局实际后台线程测试：

|难度|平均计算|P95 计算|最大计算|
|---|---:|---:|---:|
|友善|0.23 ms|0.50 ms|1.05 ms|
|中立|1.02 ms|4.96 ms|17.30 ms|
|敌对|2.77 ms|10.81 ms|28.15 ms|

Worker 首次创建到返回约 39ms，游戏在入场期间预热以减少这项开销。以上为此主机的 Node 工作线程测量，不能替代浏览器或嵌入环境实测。原始数据在 tools/generation-benchmark.json。

主要模块：generation.js 为求解验证器，board-generator.js 为生成策略与概率参数，generation-worker.js / generation-client.js 负责后台线程与超时降级，generation-seeds.js 为覆盖三个难度全部 64 个首击位置的备用种子。运行 tools/build-generation-seeds.mjs 可重新生成并验证备用种子。

## 独立存档与宿主关闭接口

三个难度各保存一局未完成游戏，键名为 `bone-gift-sessions-v1`。保存棋盘、已打开格、已确认毒礼物、累计毫秒用时和生成信息。游戏完成或失败后移除该难度存档，其他难度保留。点击有存档的难度时，先选择“继续排查”或“重新开始”；重新开始只覆盖这个难度。

开局、有效拆封、茶壶提示、返回主页时立即保存，游戏中每 5 秒保存一次时间；页面隐藏、pagehide、beforeunload 时同步补存。退出和隐藏期间不累计时间，恢复时从已保存用时继续；恢复不会重新布雷，也不会重放开局动画。首击前退出保存的是未布雷状态，回来后仍由首次点击决定棋盘。

页面模块加载完毕后，宿主可以调用：

```js
// 只保存：包含全部难度存档、成绩、音量设置，游戏继续运行。
const saved = window.MinesweeperGame.saveAll();
// { ok: true, savedLevels: [0, 2], savedAt: '...' }
// 或 { ok: false, error: '...' }

// 宿主关闭前调用并检查结果。
const result = await window.MinesweeperGame.prepareToClose();
if (result.ok && result.readyToClose) {
  // 此时所有数据已写入，计时、动画、音频和生成线程已停止。
  // 在这里调用宿主已有的关闭窗口/销毁 WebView 方法。
} else {
  // 展示 result.error，保留页面，不要关闭。
}

// 如果宿主取消关闭，可恢复原页面。
await window.MinesweeperGame.resume();
```

接口自身不会调用 `window.close()`，实际关闭由宿主负责。存储写入失败时，prepareToClose 不会停止当前游戏，也不会返回 readyToClose: true。普通游戏退出失败会显示重试提示。自动关闭事件无法等待异步任务，因此补存使用同步 localStorage；突然断电等情况依靠之前的操作检查点和 5 秒定期保存。
